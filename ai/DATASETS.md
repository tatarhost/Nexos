# AIL AI — датасеты и план обучения

Цель: компактная языковая модель примерно на 500 млн параметров с упором на программирование, но с поддержкой обычного текста и русского языка.

## Рекомендуемые источники

### 1. Код: The Stack v1.2 (BigCode)
- Карточка и условия: https://www.bigcode-project.org/docs/about/the-stack/
- Использовать только разрешённую подвыборку с permissive-лицензиями, соблюдать opt-out и условия каждого исходного репозитория.
- Не скачивать весь архив без фильтрации: полный набор слишком велик для учебного проекта.
- Перед обучением удалять дубликаты, секреты, токены, ключи, персональные данные и подозрительные файлы.

### 2. Обычный текст: FineWeb-Edu
- Датасет: https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu
- Лицензия коллекции: ODC-By 1.0; также учитывать условия Common Crawl и права на исходные страницы.
- Хорош для обучающих, объяснительных и информационных текстов; преимущественно английский.

### 3. Многоязычный текст: FineWeb2
- Датасет: https://huggingface.co/datasets/HuggingFaceFW/fineweb-2
- Лицензия коллекции: ODC-By 1.0.
- Подходит для многоязычного корпуса; при подготовке отдельно отбирать русский язык и проверять качество документов.

## Начальная пропорция корпуса

Это стартовая гипотеза для экспериментов, а не доказанный оптимум:
- 50% исходный код с проверенными лицензиями;
- 30% обычный качественный текст, включая русский;
- 15% технические объяснения, документация и вопросы/ответы;
- 5% инструкции и примеры «задача → решение».

Разделять данные на train/validation до обучения. Не использовать тестовые наборы бенчмарков в обучающем корпусе.

## Этапы

1. Сначала собрать небольшой воспроизводимый корпус и проверить очистку, лицензии и дедупликацию.
2. Обучить и оценить базовую модель; измерять loss на validation и качество на отдельных задачах по Python, JavaScript, Java, C++, Rust и русскому тексту.
3. Увеличивать размер модели только после успешного теста меньшей конфигурации.
4. Для целевой модели около 500M параметров использовать отдельную GPU-машину с постоянным диском и сохранением checkpoint. GitHub Actions не является круглосуточным сервером.
5. Хранить контрольные точки вне Git-репозитория; в GitHub Actions оставлять управление задачами, тесты и публикацию артефактов.

## Ограничения

- Число параметров само по себе не означает, что модель умеет хорошо программировать.
- Нынешняя реализация NEXUS использует UTF-8 byte-level tokenizer и случайную инициализацию. Для серьёзной модели AIL AI потребуется отдельная работа над токенизатором, корпусом, checkpoint/resume, смешанной точностью и оценкой качества.
- Не публиковать веса и датасет, пока не проверены лицензии и условия распространения.
